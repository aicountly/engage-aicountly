# Scheduled jobs of Engage (E8-OPS, F160). Installed into the deploy user's crontab by the production deploy
# (.github/workflows/deploy-production.yml -> bin/ops/post-deploy-jobs.sh -> bin/ops/install-jobs.sh --apply); check on
# the server with `bash bin/ops/install-jobs.sh --check`. `php spark engage:console-audit-deliver` reports itself to
# Console's Cron Job Monitor (engage.console_audit_deliver; app/Libraries/CronHeartbeat.php, key
# CONSOLE_CRON_MONITOR_KEY in api/.env, written by the deploy from the repo secret), so it runs WITHOUT the run-job.php
# wrapper — wrapping it with --monitor would report every run twice.
# The seller-programme crons (docs/SELLER_PROGRAM.md § 11) are not listed here yet: they stay hand-installed, and a
# hand-installed line for them is left alone.
#! app: engage
# CodeIgniter on its Postgre driver: the PHP CLI needs pgsql (not pdo_pgsql).
#! php-ext: pgsql
# Replaces the hand-installed line README.md used to give, so the job never runs twice. The spark command name is
# Engage's own.
#! legacy-pattern: spark[[:space:]]+engage:console-audit-deliver
# docs/LICENSING.md used to tell operators to hand-install the hourly expiry line; this block replaces it.
#! legacy-pattern: spark[[:space:]]+engage:licences-expire
# name                  | schedule    | command (run from the api folder)
console-audit-deliver   | */5 * * * * | {php} spark engage:console-audit-deliver
# Licensing (docs/LICENSING.md §6-§8): expiry hourly (a paid plan that ends falls back to Basic; never restricts),
# the Engage -> Manage entitlement push every minute (dormant and exit 0 until MANAGE_API_BASE_URL /
# ENGAGE_OUTBOUND_MANAGE_* are set) and the report-only drift check daily. Each reports itself to Console's Cron Job
# Monitor (engage.licences_expire, engage.entitlements_push, engage.entitlements_reconcile).
licences-expire         | 23 * * * *  | {php} spark engage:licences-expire
entitlements-push       | * * * * *   | {php} spark engage:entitlements-push
entitlements-reconcile  | 41 4 * * *  | {php} spark engage:entitlements-reconcile
# Coupons (docs/COUPONS.md §5): release lapsed quote reservations, expire old quotes and ended coupons. Hourly, offset
# from the other jobs; reports itself to Console as engage.coupons_expire.
coupons-expire          | 41 * * * *  | {php} spark engage:coupons-expire
# Token conversions (docs/TOKEN_CONVERSIONS.md): send AI Pulse the rate card — one effective multiplier per model,
# already resolved. Hourly, offset from the others. Pulse keeps the last card it was given, so a failed push leaves
# pricing unchanged. Reports itself to Console as engage.token_rates_push; inert until PULSE_API_BASE_URL is set.
token-rates-push        | 11 * * * *  | {php} spark engage:token-rates-push
# Token grants (docs/TOKEN_CONVERSIONS.md §10): deliver queued grants — vouchers and purchases — to AI Pulse. Every
# minute, because a customer who has just redeemed a voucher is watching for the tokens. Idempotent on grant_ref.
token-grants-push       | * * * * *   | {php} spark engage:token-grants-push
# AI token balance warnings (docs/TOKEN_CONVERSIONS.md §11): collect what Pulse has worked out and deliver it through
# Console's notification hub. Every 15 minutes — a customer running out of tokens should hear within the hour, and
# Pulse only queues on a threshold crossing so there is rarely anything to collect.
token-alerts-send       | */15 * * * * | {php} spark engage:token-alerts-send
# Estate analytics (analytics-aicountly sdk/README.md). BOTH jobs are inert until
# AICOUNTLY_ANALYTICS_ENABLED=1 in .env: the flush exits 0 immediately and the snapshot prints one
# line and exits 0. That is why they are safe to install on every product, enabled or not — a job
# that mailed an error nightly until somebody configured it is a job the operator would filter, and
# then nobody would see the night it broke for a real reason.
# NOTE: this block asks install-jobs.sh for `pgsql` (CodeIgniter's Postgre driver). The analytics
# jobs use PDO and need pdo_pgsql as well; the server normally has both. If it does not, the job
# says so and exits 3 rather than failing obscurely — point it at a CLI that has both with
# `bash bin/ops/install-jobs.sh --php=/path/to/php --apply`.
# The flush drains anything the after-response send could not deliver (Analytics briefly down, a CLI
# process, a request that died before shutdown). The snapshot reports this product's own database
# size, tables and row counts once a day — events can never answer those, so the product that owns
# the database reports them (analytics docs/08). Minutes are staggered per product so forty hosts do
# not all wake together.
analytics-flush         | * * * * *   | {php} app/ThirdParty/AicountlyAnalytics/analytics-flush.php --env=.env
analytics-platform      | 47 1 * * *  | {php} app/ThirdParty/AicountlyAnalytics/analytics-platform-snapshot.php --env=.env --push
# This product also OWNS facts nothing else can report: commercial figures (paying and free customers, money collected, token balances).
analytics-snapshot      | 49 1 * * *  | {php} scripts/analytics_snapshot.php --env=.env --push
